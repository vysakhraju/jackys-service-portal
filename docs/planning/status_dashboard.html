Designed with a the-fool pre-mortem before any screen was built

What the pre-mortem caught before it shipped

  • 01
    An EXPIRED estimate has no resend/extend endpoint on the backend — gating "Create" on an empty list, not on "no active estimate", would have been a dead end.

    Fixed: "Create Estimate" now keys off whether a DRAFT/SENT/APPROVED estimate exists, not whether the list is empty — an EXPIRED or REJECTED-with-no-revise-yet row no longer blocks a fresh one.

  • 02
    The staff API client's bearer-token + redirect-to-login behavior had no business anywhere near a customer's browser.

    Fixed: the public link page (/estimate/:token) now runs on a brand-new, zero-interceptor axios client — asserted by its own test to carry no auth header and no redirect logic at all.

  • 03
    The anti-consent-laundering contact check is exact-format — a staff member guessing at phone formatting would 400 every time with no hint why.

    Fixed: the Record Response form prefills the exact on-file phone/email as one-click buttons instead of a blank field.

  • 04
    A customer responding via the link at the same moment staff records a phone decision produces a 409 — a raw error would look like a broken form.

    Fixed: both response forms now refetch on a 409 and show the real, current decision instead of a stale form.

Worth knowing

Two new standing practices, both held up on the first real run

the-fool now runs as a design pre-mortem before any phase with tricky logic gets built, not after — this phase's four findings (above) were all fixed before a single screen existed, and none of them showed up as bugs once tested against the real backend. test-master coverage also starts here rather than being backfilled onto Phases 1-4 — the frontend had zero automated tests before this phase; it now has 20, all passing, and every phase from here on ships with its own.

Also as before: this build session has no network path to anything running on your machine — only a file bridge (confirmed back in Phase 3). Each frontend phase ships with a small PowerShell script (verify-phaseN.ps1) you run yourself with both dev servers up; you paste back the output and anything that fails gets fixed from that. Same pattern git push already uses — verify-phase5.ps1 passed all 28 checks on the first try.
